# 宏观周期与大类资产配置网站实施方案（Vibe Coding）

> 目标：做出一个接近 https://www.htficc.com/ 的产品形态，用数据驱动地跟踪中国宏观经济周期，并给出可解释的大类资产配置框架。

## 1. 先拆目标：你到底要“像”什么

一个成熟的宏观跟踪网站通常不是“一个网页”，而是 4 层能力叠加：

1. **数据层**：稳定抓取与更新宏观、金融、资产价格数据。
2. **模型层**：把原始数据转成“周期状态 + 配置建议”。
3. **产品层**：用户能看懂、能追踪、能对比历史。
4. **运营层**：持续迭代、版本管理、信号复盘。

如果你按这个结构做，哪怕前端样式不同，也能达到同等“效果”。

## 2. MVP（最小可用版本）建议：4 周内可上线

### 第 1 周：定义框架 + 指标体系

先别急着写代码，先定“方法论文档”（非常关键）：

- 经济增长维度（如工业增加值、PMI、社零、固定资产投资）
- 通胀维度（CPI、PPI）
- 流动性维度（社融、M2、利率）
- 外部环境（美元指数、油价、全球风险偏好）

输出内容：

- 一个 **指标字典**（频率、发布滞后、单位、是否季调）
- 一个 **周期判定规则**（例如 4 象限：增长↑/↓ × 通胀↑/↓）
- 一个 **资产映射表**（每个象限下：权益/利率债/信用债/商品/黄金的偏好）

### 第 2 周：数据管道（自动更新）

你需要一个每天自动跑的数据流程：

- 抓取：AkShare / Tushare / Wind（如有）/ 公共数据源
- 清洗：缺失值处理、频率对齐（月频/周频/日频）
- 存储：PostgreSQL（结构化）+ 对象存储（原始文件）
- 调度：GitHub Actions 或 Airflow（先用 Actions 够快）

产出标准：

- 每天固定时间更新
- 任意指标可追溯原始来源
- 失败自动告警（企业微信/飞书）

### 第 3 周：模型与信号

建议从“可解释”开始，不要一上来黑箱 ML：

1. 标准化各指标（同比、环比折年、Z-Score）
2. 计算增长/通胀/流动性三个综合分数
3. 用阈值或马尔可夫状态切换识别周期阶段
4. 生成资产配置建议：
   - 战术（1-3 个月）
   - 战略（6-12 个月）

同时输出“置信度”：

- 数据完整度
- 信号一致性
- 历史回测稳定性

### 第 4 周：前端与交互

前端核心不是炫技，而是“读者 30 秒看懂”：

- 首页：当前周期状态 + 配置建议（一句话摘要）
- 周期页：四象限仪表盘 + 历史阶段切换时间轴
- 指标页：每个指标的最新值、趋势、历史分位
- 资产页：各资产相对胜率、回撤、相关性热图

推荐技术栈（vibe coding 友好）：

- **Next.js + TypeScript + Tailwind + ECharts**
- 后端可选：Next API Routes / FastAPI
- 鉴权与后台：Supabase 或 Clerk

## 3. 你要重点做的“像 htficc 的能力”

### A. 叙事一致性（最容易被忽略）

很多站点失败不是图表不够多，而是“结论口径经常变”。

你需要固定模板：

- 本期周期判断
- 与上期相比变化
- 触发变化的 3 个关键指标
- 对资产配置的影响

### B. 历史可复盘

每次信号要“落库 + 可回看”：

- 当时看到的数据
- 当时给出的结论
- 之后 1M/3M/6M 资产表现

这会让产品可信度大幅提升。

### C. 发布节奏

建议固定节奏：

- 日更：高频市场与流动性温度
- 周更：资产配置周报
- 月更：宏观周期月报（核心）

## 4. Vibe Coding 的正确用法（避免“看起来快，后期崩”）

你可以把 AI 当“多角色小团队”：

1. **产品经理模式**：让 AI 先写 PRD、页面信息架构、指标字典。
2. **量化研究员模式**：让 AI 输出指标处理与周期判定伪代码。
3. **数据工程师模式**：生成 ETL 脚本、调度配置、数据校验脚本。
4. **前端工程师模式**：按页面逐个生成组件，不要一次性生成整站。
5. **审计模式**：让 AI 自查“数据泄漏、未来函数、口径漂移”。

关键原则：

- 小步提交（每次只做一个功能）
- 每一步都有可运行结果
- 每一步都有人类验收标准

## 6. 常见坑与规避

1. **未来函数问题**：用发布时间而不是统计期时间对齐。
2. **过拟合**：别用太多参数，先用稳定规则。
3. **数据修订**：宏观数据会被修订，要保留“当时快照”。
4. **结论跳变**：设置状态切换缓冲区（hysteresis）。
5. **只讲收益不讲回撤**：必须同时展示最大回撤与波动。

## 8. 对标 https://www.htficc.com/briefing.html 的产品化路径（Vibe Coding 实战）

你可以把 `briefing` 这类页面理解成：

- **投研结论中台**（结构化观点）
- **数据图表前台**（可视化证据）
- **发布与归档系统**（按周/月持续输出）

要用 vibe coding 做到类似效果，建议按下面 6 个模块落地：

### 8.1 内容结构先行：固定“简报模板”

先把每期简报模板固定，避免每次写法变化：

1. 本期结论（3 行内）
2. 核心证据（3-5 张关键图）
3. 大类资产建议（权益/利率债/信用债/商品/黄金）
4. 风险提示（何种条件下结论失效）
5. 与上期变化（增量信息）

> 这一步比前端样式更重要，决定了产品是否“像研究平台”而非“图表集合”。

### 8.2 页面信息架构：先做 Briefing，再扩到全站

先做单页 MVP（即 `briefing`），包括：

- 顶部：本期标题、发布日期、版本号
- 主体：分章节滚动阅读（增长、通胀、流动性、资产）
- 右侧：目录锚点 + 快速跳转
- 底部：历史简报列表（可回溯）

然后再扩展到：

- Dashboard（实时看板）
- Indicators（指标库）
- Backtest（历史表现）

### 8.3 数据到结论的链路：可追溯、可复现

每条结论都要能回溯到：

- 指标代码（Wind/iFinD）
- 拉取时间戳
- 计算版本（规则 v1/v2）
- 生成结论时使用的数据快照

建议数据产物三层：

- `raw`：原始拉取结果
- `feature`：同比/环比/Z-score
- `briefing_payload`：页面直接消费的 JSON

### 8.4 技术实现建议（最适合 Vibe Coding）

推荐架构：

- 前端：Next.js + Tailwind + ECharts
- 内容：Markdown/MDX（每期简报一篇）
- 数据任务：Python（WindPy/iFinDPy）+ 定时任务
- 存储：PostgreSQL + 对象存储

Vibe coding 分工提示：

1. 让 AI 先生成 `BriefingPage` 页面骨架与组件清单
2. 再让 AI 生成 `briefing_payload` 的 TypeScript 类型
3. 再让 AI 生成数据校验脚本（缺失值、发布时间延迟）
4. 最后再优化视觉样式与动效

### 8.5 你最该补的“专业感”细节

要接近 htficc 的观感，关键不是炫技，而是这 5 点：

- 用词统一（阶段命名与建议口径固定）
- 图表注释充分（每图一句话结论）
- 章节节奏清晰（先结论后证据）
- 历史版本可切换（上一期/近 12 期）
- 每期有“更新日志”（本期新增与修订）
